# Standalone 799X RC57 live E2E results

On November 20, 2026, seven of the eleven 799X scenarios ran to completion in Warcraft III. The repository checker recorded **365 passing and 85 failing assertions**. All seven completed scenarios had at least one failed assertion. The remaining four scenarios could not compile against this release.

## Build and test method

- The tested release was `Reforged Footmen Frenzy v7.9.9X-rc57 Witch Doctor Wards.w3x`. Its SHA-256 was `2709b4152db9c18c3d56cf99405e4fb71a746d68c8fef6735d1c3a05d22d45d3`. [NorthStar RC57 source](https://github.com/NorthStarEnergy/Footmen-Frenzy/tree/d5a1d53027e801238ba29ce091e953b1bc0c479a/projects/799x)
- The suite ran from revision `1d2b69b2d0a4ff8ac2a4a38c1024ec8d96a582e8` from upstream PR #1. The script extracted from the release matched the standalone port byte for byte. The default league project at this revision builds a different map with shared team taverns. [Suite](https://github.com/NorthStarEnergy/footmen-frenzy-contributions/tree/1d2b69b2d0a4ff8ac2a4a38c1024ec8d96a582e8/tests/e2e) · [Standalone port](https://github.com/NorthStarEnergy/footmen-frenzy-contributions/tree/1d2b69b2d0a4ff8ac2a4a38c1024ec8d96a582e8/projects/ports/northstar/799x)
- The runner used WSL for compilation and judging and Windows StormLib to pack and verify the test maps. The native Windows Warcraft III client, version `3.0.1.24371`, played local single-player games with computer slots. Each fixture began as a complete copy of the release. Test changes covered scenario scripts, the test client identity, the lobby slots, the suite’s Raze ability, and a read-only tavern-position measurement. The packed script, ability data and lobby data were read back and verified. The repository’s scenario assertions were used as written.
- The separate 3.0 compatibility probe requires a pre-3.0 reference installation. The ladder scorer requires the fleet’s pinned `efl-bot` checkout. Neither was available. Multiplayer behavior with a human disconnecting was outside this run.

## Taverns and Witch Doctor wards

- Warcraft recorded a separate player-named Hero Tavern for all 12 slots in the observer game. Distances from each player's starting location ranged from 319.816 to 320.325 game units. RC57 requests 320.
- The skills scenario exercised 291 hero skills and recorded 1,530 casts. Witch Doctor’s three ward orders (`A0M2`, `AWsX`, `AWsZ`) each took effect at all six levels. All 18 casts matched the expected mana cost and cooldown. Ward summons, healing and damage amounts, tooltips, and manual controls need separate verification.
- Of 9,097 numeric cells read from the engine, 61 differed from the suite’s expected data. The cooldown field differed on `ATf1`, `ATf2`, `ATfb`, and `ATfg`. Fields `Ear2` and `Ear3` differed on `A02C`, `A03J`, `A0V1`, and `A0VM`. During casting, `ATfb` started a zero-second cooldown at levels 1–3, where the suite expected 220, 180, and 120 seconds.

## League compatibility and tower behavior

The league checker expects both `deny_tower` and `tm_creeps` in each player's stats row. RC57 omitted those keys. Each affected scenario counts that as one failed assertion per player. That single file-format difference accounts for 72 of the 85 failed assertions across six scenarios.

In the tower scenario, tower splash killed a nearby enemy and spared friendly footmen. An explicit attack order against a friendly footman killed only its target and updated the deny counters. The game issued zero automatic friendly attack orders during the measurement.
